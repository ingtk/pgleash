# pgleash

ユーザーが承認したローカル開発用PostgreSQLだけを操作する、小さなGo製CLIです。
接続先とCLI自身のOS操作経路を制限し、ローカルDBで許すSQL操作は制限しません。

現在は、設定の検査・プロファイル一覧の表表示・ヘルプに対応しています（[#2](https://github.com/ingtk/pgleash/issues/2)）。
SQL実行は[#3](https://github.com/ingtk/pgleash/issues/3)、JSON/CSVは[#4](https://github.com/ingtk/pgleash/issues/4)・[#5](https://github.com/ingtk/pgleash/issues/5)で追加します。

## 実行

Go 1.23以上、macOSまたはLinuxを使用します。

```sh
go run ./cmd/pgleash --help
go run ./cmd/pgleash --profiles
go run ./cmd/pgleash --profiles --format table
```

ビルドする場合は、次のように実行します。

```sh
go build -o /tmp/pgleash ./cmd/pgleash
/tmp/pgleash --profiles
```

`--help` は設定ファイルなしで使えます。`-h` は受け付けません。
一覧は名前順に、名前・ポート・ユーザー名・DB名だけを表示し、DBには接続しません。
パスワードを含む設定内容や接続文字列を診断へ表示せず、一覧の制御文字は見える表現に変換します。
`--profile NAME` は登録名を検査します。一覧では選択にかかわらず全プロファイルを表示します。
現在選べる出力形式は `table` のみです。エラーは標準エラーへ出力し、終了コード1で終了します。

## 設定

設定は、実行ユーザーのホームにある `~/.config/pgleash/config.toml` だけから読みます。
例えば、ユーザー自身が次の内容を保存します。パスワード例は実際のローカル開発用の値に置き換えてください。

```toml
default_profile = "dev"

[profiles.dev]
port = 5432
user = "app_local"
password = "local-development-password"
database = "app_local"

[profiles.other]
port = 6543
user = "other_local"
password = "another-local-password"
database = "other_local"
```

- `default_profile` を省略すると `dev`。既定名は登録済みである必要があります。
- 各プロファイルの `port`・`user`・`password`・`database` は必須です。明示的な空パスワードは許可します。
- ポートは1〜65535。空の名前・ユーザー名・DB名、未知の設定項目、型の誤りはエラーです。
- ホストは将来のSQL実行でも `127.0.0.1` 固定です。`host` やDSNは設定に書けません。
- ファイルは実行ユーザー所有の通常ファイルで、権限は `0400` または `0600` にします。
- macOSではモードを迂回するACLも検査し、設定の読み取り・書き換えや親ディレクトリの差し替えを許すACLは拒否します。標準的な「削除を拒否する」ACLは使用できます。
- パスの途中も含め、シンボリックリンクは拒否します。ホームの登録パスも実体のパスである必要があります。
- 親ディレクトリは実行ユーザーまたはroot所有で、他ユーザーがエントリを差し替えられない必要があります。root所有のstickyディレクトリは、所有者のエントリを保護できるため許可します。
- 設定の検査は、順に開いたディレクトリと実際に読むファイルのディスクリプタに対して行います。

設定ファイルの場所をフラグや環境変数で変更する機能はありません。
ホームは実行ユーザーのUIDから取得し、`HOME`・`XDG_CONFIG_HOME` を設定の選択に使いません。
起動時に、このCLIプロセス内の `PG` で始まる環境変数を削除します。親シェルやOSの恒久設定は変更しません。

## 保証範囲

設定に登録することを、ユーザーによる接続先の承認として扱います。
設定と実行バイナリをエージェントに書き換えさせない環境で使用してください。
登録済みの接続先はすべて選択可能になるため、ローカル開発用だけを登録します。

pgleash自身には、ローカルコマンド実行、SQLファイル・標準入力からの取り込み、結果ファイル出力を設けません。
OSによるユーザー情報の取得など、OS・ライブラリ内部の参照はこの入出力機能の制限と区別します。

接続先の設定はDockerであることの証明ではありません。同じポートが別のサーバーへ転送され、DB名・ユーザー名も一致する場合は区別できません。
また、DBサーバーの強い権限や危険な関数、書き込み可能なDockerのbind mountなどを通じ、サーバー側の操作がホストに影響する可能性があります。
エージェントに別のスクリプトやDBクライアントの実行を許可している場合、その経路をpgleashが制限することはありません。

## 開発時の確認

```sh
go test ./...
go vet ./...
```

テストはCLIの入口から、引数・出力・終了コードを検証します。設定用の一時ホームはテスト内でだけ差し替えます。
本番コードへの禁止import・コマンド実行API・環境変数による設定上書きAPIの追加も構造チェックで検出します。

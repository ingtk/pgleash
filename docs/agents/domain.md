# Domain Docs

## Layout

This is a single-context repository:

- `GLOSSARY.md` at the repository root
- Architecture decision records under `docs/adr/`

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.
If these files do not exist, proceed silently.
Do not create placeholders or suggest creating them upfront.
The domain-modeling skill creates them when terms or decisions are resolved.

## Vocabulary and decisions

Use the glossary's terms in issue titles, proposals, hypotheses, and tests.
If a concept is missing, reconsider the term or note the gap for domain-modeling.
Explicitly flag proposals that contradict an existing ADR.
